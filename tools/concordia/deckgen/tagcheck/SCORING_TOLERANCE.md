# Scoring tolerances for the reverse check (user order 2026-10-23)

Some differences between a reader's text and the printed Oracle text are not errors. They are made identical before comparing (`reverse_check.tolerate()`, used by `norm()` for the accuracy score, the consistency signature and V1t in `consistency.py`). Everything else still counts.

| # | Tolerated | Why | Where | Not tolerated |
|---|---|---|---|---|
| a | `this creature` / `this permanent` / `this artifact` ... (any `this|that <type>`) / `~` in place of the card's name | CR 201.5: text that names its own object means that object. Oracle itself prints `this creature` where a card names itself in Oracle templating (Mark Rosewater on Nine Lives Familiar, as given by the user; the page itself could not be fetched from the sandbox, so this reason rests on the user's note and on CR 201.5). The scorer already replaced the name; the tolerance makes the phrase equal to it | `tolerate()`, `norm()`; style linter S1b reports it but it is no error | a wrong card type word is not checked (a wrong "this creature" for an artifact is not caught); using another card's name is a leak and still counts |
| b | `whenever` = `when` | CR 603.1 writes the template as [When/Whenever/At]; the rules are identical for the first two. Per the user's note from Mark Rosewater: `When` for events expected once (enters), `whenever` for events that can repeat (attacks), `at` for steps and phases; what matters is how the event is worded. Pool counts agree (ORACLE_STYLE_STATS.md): enters 4247 When / 759 Whenever, attacks 26 / 1200, dies 643 / 390, cast 109 / 841 | `tolerate()`; the scorer already ignored both words (stop words); V1t, the signature and the linter now do too | `at the beginning of` is a different trigger class (phase / step) and is not equal to `when`. A trigger event that is worded differently is not tolerated |
| c | `return ... to the battlefield` = `put ... onto the battlefield` | CR 110.2a: if an effect instructs a player to put an object onto the battlefield, it enters under that player's control unless the text says otherwise; "return to the battlefield" is the same instruction. CR 610.3c shows the other wording (returned under its owner's control). Pool: put 1267, return 1104 for the battlefield. The Reddit post the user linked could not be fetched (sandbox blocks reddit.com), so the usage rule behind it is not checked here | `tolerate()` (window of 80 characters, no sentence break) | `return ... to hand` / `to library` and `put ... into hand` are untouched; `under your control` vs `under its owner's control` is a separate fact (the `controller` tag) and still counts |

## Effect on the r12 baseline (3 readers x 353 cards)
Accuracy 0.930 -> 0.931. V1 strict 61.5%, V1 tolerant 62.1% (the three tolerances alone move little: readers already agree on these words). The large V3 gain (73.6% -> 87.9%) comes from fixing the signature parser, not from the tolerances; see `GRAMMAR_BASELINE.md`.

## Rule for the grammar (phase 2)
The grammar still chooses one wording so that variance falls: `when` for one-time events (enters, dies, becomes), `whenever` for repeatable events (attacks, cast, deals damage, draws), `at the beginning of` for steps and phases; `return` and `put` chosen by the origin zone from the pool counts. The tolerances only stop the scorer from calling the other wording wrong.
