# Random quests in Forge Adventure: analysis for Concordia

Read-only analysis, branch `campaign-design`. Paths are relative to `forge-gui-mobile/src/forge/adventure/` (call it `J/`)
unless they start with `forge-gui/`. Line numbers are from this checkout.

**Short version.** Forge has no quest *generator*. A "random" quest is a **random pick of a hand-written template** from
`world/quests.json`, with a few slots filled at pick time: target POI (by tag), target enemy (by tag), player name,
biome. Everything else (text, rewards, stage graph) is fixed in the template. Concordia ships **no side-quest
templates**, so its notice boards currently show "come back tomorrow".

## 1. How a random quest is picked and built

### 1.1 Flow

| Step | Where | What happens |
|---|---|---|
| 0. Load | `J/util/AdventureQuestController.java:299-311` `loadData()` | Reads `world/quests.json` (`Paths.QUESTS`, `util/Paths.java:13`) into `allQuests`. Every entry with `storyQuest != true` also goes into `allSideQuests`. |
| 1. Board object | `forge-gui/res/adventure/common/maps/obj/quest.tx` (class `quest`, property `questtype`) | A TMX object placed in a town map. `questtype` is a free string, the **source tag**. |
| 2. Build actor | `J/stage/MapStage.java:743-749` | Object type `quest` with a `questtype` property becomes a `QuestActor(poiID, changes, questtype, ...)`. It is created **invisible** (`setVisible(false)`); the map's board sprite is the visible part. An object without `questtype` is silently ignored. |
| 3. Player bumps it | `J/character/QuestActor.java:36-47` `onPlayerCollide()` | Calls `getQuestNPCResponse(poiID, changes, questtype)`, wraps `questData.offerDialog` in a `MapDialog`, shows it. Actor removes itself from the map when the dialog ends (`:26-32`). |
| 4. Offer logic | `AdventureQuestController.java:491-562` `getQuestNPCResponse` | See 1.2. Returns either a canned "no quest" response or a fresh copy of a template, initialized. |
| 5. Initialize | `AdventureQuestData.java:170-178` `initialize()` -> `initializeStage` `:180-255` -> `replaceTokens` `:257-339` | Picks stage target POI and enemy, then substitutes `$(token)` text. |
| 6. Accept | Dialog option with `action[].issueQuest = "<id>"` (`DialogData.java:91`, `MapDialog.java:505-508`) | Fires the "quest accepted" listener, which calls `Current.player().addQuest(...)`. For a board offer the `prebuiltQuestData` copy (with its chosen targets) is added (`MapDialog.java:140-148`); otherwise the template is re-generated by ID (`AdventureQuestController.java:455-465` `generateQuest`, `AdventureQuestData.java:75-104` copy constructor). |
| 7. Track | `J/player/AdventurePlayer.java:1628-1643` `addQuest` | Adds to the list, auto-tracks if nothing is tracked or `autoTrack`, then `activateNextStages()` and shows queued dialogs. |
| 8. Progress | `AdventureQuestController.java:337-453` `update*()` | Game code fires typed events; each quest's `updateStages` (`AdventureQuestData.java:393-411`) feeds them to active stages (`AdventureQuestStage.java:268-386`). |
| 9. Finish | `AdventureQuestController.showQuestDialogs` `:78-148` | When all stages are COMPLETE: shows `epilogue` (its `grantRewards` action pays the reward), removes the quest, fires `QUESTCOMPLETE`. A failed quest shows `failureDialog`. |

### 1.2 Offer rules (`getQuestNPCResponse`, `AdventureQuestController.java:491-562`)

Checked in this order:

| # | Check | Result |
|---|---|---|
| 1 | Player already has an active side quest whose `sourceID == this POI's ID` and not complete | "Not finished yet" reminder (`advQuestNotFinished`) |
| 2 | `nextQuestDate[poiID] >= LocalDate.now().toEpochDay()` | "Come back tomorrow". **Real-world calendar day**, not in-game time. |
| 3 | `tooManyQuests`: active non-story, non-complete, non-failed quests `>= maximumSideQuests` (**5**, hard-coded `:~170`, "todo: move to configuration") | "Log full" |
| 4 | `allSideQuests.isEmpty()` | "Come back tomorrow". **Concordia-local guard** added in this fork (`:~527`); vanilla would crash on an empty list. |
| 5 | Pick | `nextQuestDate[poiID] = today` is set **as soon as a quest is rolled**, even if the player declines. Candidates = side quests with empty `questSourceTags` **or** a tag equal to the board's `questtype`. If none match, **any** side quest is used. One is chosen uniformly (`Aggregates.random`, no weights). |

After finishing a quest (not failed), `locationHasMoreQuests()` (85% chance, hard-coded, `:~145`) clears
`nextQuestDate` so the board offers again the same day. Failed or abandoned quests keep the lock.

Not limited: how many different boards can offer at once (only the global cap of 5), repeats of the same template (the
same template can be offered again, even while the player holds it, unless the player holds one from the same POI).

### 1.3 What the generator actually fills in (`initializeStage`, `AdventureQuestData.java:180-255`)

| Slot | Mechanism | Detail |
|---|---|---|
| Target POI | `AdventureQuestStage.setTargetPOI` (`:96-139`) | Order: `worldMapOK` -> no POI. `POIToken` -> reuse another stage's POI. `here` -> `mostRecentPOI` (the town just entered, set at `TileMapScene.java:161`). Else candidates = all world POIs, minus inactive ones (unless `allowInactivePOI`), minus any POI missing **any** listed `POITags` (AND match against `PointOfInterestData.questTags`). If `anyPOI` is false one is chosen; if the candidate list is empty it falls back to "all POIs" and **leaves target null**. |
| POI distance bias | same, `:124-136` | Candidates sorted by distance from player (`DistanceSort`, `AdventureQuestController.java:~215`). `count1` = target percentile of the list (0 = nearest, 100 = farthest), `count2` = +/- percent variance, random within that. If both are 0 or out of range -> uniform random. This is the only "scaling by distance". |
| Target enemy (`Defeat`/`Escort`, not `mixedEnemies`) | `generateTargetEnemyData` `:362-385` | All enemies whose `questTags` contain every stage `enemyTags` and none of `enemyExcludeTags`; uniform random; falls back to **any enemy** if none match. |
| Hunt sprite | `generateTargetEnemySprite` `:345-360` | Same enemy pick, wrapped in an `EnemySprite` with `lifetime = count3` (seconds before it despawns -> stage FAILED). Spawned by `WorldStage.java:~671` via `addQuestSprites`. |
| Text | `replaceTokens` | See table in 2.4. |
| Dungeon reset | `:234-239` | If target POI type is `cave`/`dungeon`, its deleted-object list is cleared so the dungeon is full again. |

### 1.4 Who offers, difficulty and rewards

- **Who offers**: only the `quest` TMX object (board / NPC) in a map. No NPC, POI or flag logic decides *who*; the map
  author decides *where* by placing the object and setting `questtype`. Hand-placed dialogs can also call
  `issueQuest` for a **fixed** ID (that is how story quests chain).
- **Difficulty**: none in the quest code. No level, tier or Seal input. Enemy choice depends only on tags. The enemy
  *deck strength* is whatever `EnemyData` says (and, in Concordia, `TierLock.beforeDuel`, see 5).
- **Rewards**: not a field that is read. `AdventureQuestData.reward` / `rewardDescription` are display only
  (`getReward()` has no caller that pays it; `rewardDescription` is just text). Real payment is a
  `grantRewards` / `grantRewardsChoice` entry inside the **epilogue dialog action** (`MapDialog.java:490-503`), which uses
  the normal `RewardData.generate(...)` with `useSeedlessRandom = true` (`RewardData.java:190-192`), so quest rewards
  are never seeded. Vanilla scales only by `rewardMaxFactor` on `addMaxCount` (`RewardData.java:202`). Reputation is
  `addMapReputation` + `POIReference` (`$(poi_N)` resolves to a POI ID, `AdventureQuestData.java:330-338`).
- **Failure**: `Hunt` despawn (`DESPAWN` event) or `count4` losses; `abandon()` just sets `failed` (`:~395`, "todo:
  cleanup or reputation loss"). Penalties exist only as `addMapReputation` in `failureDialog` actions.

## 2. Quest data schema (`world/quests.json`)

The file is a JSON array of `AdventureQuestData` (libGDX `Json`, fields by name, unknown fields ignored).

### 2.1 Quest-level fields (`data/AdventureQuestData.java:23-63`)

| Field | Type | Meaning |
|---|---|---|
| `id` | int | Template ID. `issueQuest` refers to it. Auto-assigned (max+1) when `<1` and `isTemplate`. Concordia: 28, 1000+ (side quests planned 1200+, `DESIGN.md:589`). |
| `isTemplate` | bool | `true` for everything in the file; copies are non-templates. `generateQuest` only finds templates. |
| `name`, `description`, `synopsis` | string | Log text (tokens allowed). `synopsis` is dev-only. |
| `storyQuest` | bool | `true` = never offered by boards, not counted against the cap, not shown as "side quest". |
| `autoTrack` | bool | Becomes the tracked quest when added. (Not copied by the copy constructor, `:75-104`; harmless because the player's copy comes from `generateQuest`, but a board-offered copy loses it.) |
| `offerDialog` | DialogData | Shown at the board. Must contain an option with `issueQuest = <own id>` to accept. |
| `prologue` | DialogData | Queued once when added. |
| `epilogue` | DialogData | Queued once when all stages are complete; put `grantRewards` / reputation / `issueQuest` (chain) here. |
| `failureDialog` | DialogData | Shown on failure. Put reputation loss here. |
| `declinedDialog` | DialogData | Defaulted in the constructor; shown if declined. |
| `reward`, `rewardDescription` | RewardData / string | **Display only** (see 1.4). |
| `stages` | AdventureQuestStage[] | The objectives (2.2). |
| `questSourceTags` | string[] | Board `questtype` values allowed to offer it. Empty = any board. |
| `questPOITags`, `questEnemyTags` | string[] | Declared and copied, **never read**. Use stage-level tags. |
| `sourceID` | string | Runtime: POI ID of the offering board. |

### 2.2 Stage fields (`data/AdventureQuestStage.java:20-63`)

| Field | Used by | Meaning |
|---|---|---|
| `id` | all | Stage number, referenced by `prerequisiteIDs` and tokens `$(poi_<id>)`, `$(enemy_<id>)`, `$(biome_<id>)`. |
| `name`, `description` | all | Log text. |
| `objective` | all | Enum `ObjectiveTypes` (2.3). |
| `prerequisiteIDs` | all | Stage becomes ACTIVE when all listed stages are COMPLETE. Empty = active at start. Several stages can be active at once (the "one active stage" comment at `AdventureQuestData.java:119` is stale). |
| `POITags` | POI objectives | AND-list matched against `PointOfInterestData.questTags`. |
| `anyPOI` | POI objectives | `true`: **any** POI matching the tags counts, nothing is picked. `false`: one POI is picked at accept time. |
| `here` | POI objectives | Target = the town the quest was just accepted in. |
| `POIToken` | POI objectives | `$(poi_N)`: reuse stage N's picked POI. |
| `worldMapOK` | most | No POI needed; progress counts anywhere (including the world map). |
| `allowInactivePOI` | POI objectives | Also pick POIs whose `questFlagsToActivate` are not yet met. |
| `count1`, `count2` | picker | Distance percentile and variance (1.3). `Fetch`: items required (`count1`). |
| `count3` | most | Times to repeat (wins, arrivals, uses). `Hunt`: **despawn seconds**. |
| `count4` | Defeat, Hunt, Event* | Losses allowed before FAILED (0 = never fails by losing). |
| `enemyTags`, `enemyExcludeTags` | Defeat, Hunt, Escort | Matched against `EnemyData.questTags`. |
| `mixedEnemies` | Defeat | `true`: any enemy matching tags counts and spawns are boosted (`getBoostedSpawns`, `AdventureQuestController.java:~70`). `false`: one enemy type picked. |
| `itemNames`, `equipNames`, `deliveryItem` | Fetch, Use, Delivery | Item names. `Delivery` currently behaves like `Travel` (`:374-378`). |
| `mapFlag`, `mapFlagValue` | MapFlag, QuestFlag, CharacterFlag | Flag name and minimum value. |
| `prologue`, `epilogue`, `failureDialog` | all | Per-stage dialogs, shown once. |

### 2.3 Objective types (`AdventureQuestController.java:100-127`, handling `AdventureQuestStage.java:280-384`)

| Objective | Implemented | Completes when | Event source |
|---|---|---|---|
| `Travel` | yes | Player enters the target POI (`ENTERPOI`, `count3` times) | `TileMapScene.java:146` |
| `Delivery` | alias of Travel | same | same |
| `Leave` | yes | Player leaves a POI map (`LEAVEPOI`) | `MapStage.java:937` |
| `Defeat` | yes | `count3` duel wins vs matching enemy (`count4` losses fail) | `updateQuestsWin/Lose` |
| `Hunt` | yes | Beat the one spawned world-map sprite before it despawns | `WorldStage` + `updateDespawn` |
| `Clear` | yes | Win and no non-scripted enemy left on the map (`event.clear`) | `updateQuestsWin(defeated, enemies)` |
| `Arena` | yes | Win the arena (`count3`) | `ArenaScene.java:199` |
| `EventFinish` / `EventWin` / `EventWinMatches` | yes | Adventure event (draft / tournament) done / won / matches won | `PlayerStatistic.java:176` |
| `Fetch` | yes | Hold `count1` of `itemNames` (checked on activation and on `RECEIVEITEM`); `USEITEM` counts `count3` | item events |
| `Use` | yes (buggy: operator precedence at `:380-382`, `itemNames.isEmpty()` short-circuits true) | Use an item | `updateItemUsed` |
| `MapFlag`, `QuestFlag`, `CharacterFlag` | yes | Named flag >= `mapFlagValue` | `updateQuests*Flag` |
| `CompleteQuest` | yes | Another quest finishes (`anyPOI` or its `sourceID == target POI`) | `updateQuestComplete` |
| `HaveReputation`, `HaveReputationInCurrentLocation` | yes | Town reputation >= `count3` | `ENTERPOI` / `REPUTATION` (only fired on enter) |
| `Escort`, `Rescue`, `Patrol`, `Siege`, `Find`, `Gather`, `Give` | **no** | enum value only; no completion code (`Patrol` has a TODO) | n/a |

**Dungeon/POI-less note:** `checkIfTargetLocation` (`AdventureQuestStage.java:163-180`) is evaluated for *every* event
before the switch: inside a map the event POI must equal the target POI (or match all `POITags` if none was picked);
on the world map only `worldMapOK` stages progress.

### 2.4 Tokens (`AdventureQuestData.java:257-339`)

`$(poi_N)` = display name of stage N's POI; `$(biome_N)` = its biome; `$(enemy_N)` = enemy name; `$(playername)`,
`$(currentbiome)`, `$(playerrace)`. Applied to name, description, rewardDescription, all dialogs (text and option
names) and stage text. In dialog actions only `POIReference` is token-resolved (to a POI ID).

### 2.5 Dialog conditions and actions (`data/DialogData.java:60-170`)

- **Conditions** (`ConditionData`, evaluated in `MapDialog.isConditionOk`): `item`, `actorID`, `hasBlessing`, `hasGold`,
  `hasShards`, `hasMapReputation`, `hasLife`, `colorIdentity`, `checkCharacterFlag` / `checkQuestFlag` / `checkMapFlag`
  (non-zero), `getCharacterFlag` / `getQuestFlag` / `getMapFlag` `{key, op, val}`, `not`.
- **Actions** (`ActionData`): `addItem`, `removeItem`, `addLife`, `addGold`, `addShards`, `deleteMapObject`,
  `activateMapObject`, `battleWithActorID`, `giveBlessing`, `setColorIdentity`, `advance/set` Character/Quest/Map flag,
  `setEffect`, `grantRewards`, `grantRewardsChoice`, `issueQuest`, `addMapReputation` (+`POIReference`),
  `returnStolenFrom`, `gateTo`/`gateEnter`/`gateMap`/`gateEntry`, `setStarterColor`, `setStarterDeck` (last four are
  Concordia additions).
- **Gap for quests**: `ConditionData` is evaluated on dialogs, but the **offer logic never evaluates conditions on a
  quest** (no `requirements` field). `offerDialog` can contain condition-gated options, but the quest is already
  rolled and the daily lock already set by then.

### 2.6 Annotated example (Shandalar quest 4 "On the Hunt", abridged; `Shandalar/world/quests.json`)

```jsonc
{
  "id": 4, "isTemplate": true,                      // template, found by generateQuest(4)
  "name": "On the Hunt",
  "description": "Find and slay the $(enemy_2) before it escapes.",   // token from stage 2's enemy
  "questSourceTags": ["forest_town_generic", "forest_capital", ...],  // only forest boards offer it
  "offerDialog": { "text": "... A $(enemy_2) has been causing trouble ...",
    "options": [
      { "name": "(Accept Quest)", "action": [{ "issueQuest": "4", "POIReference": "$(poi_1)" }] },
      { "name": "(Decline Quest)", "action": [{ "addMapReputation": -1, "POIReference": "$(poi_1)" }] } ] },
  "epilogue": { "text": "... (+3 Local Reputation)",
    "action": [{ "addMapReputation": 3 }],
    "options": [{ "name": "(Complete Quest)",
      "action": [{ "grantRewards": [ { "type": "card", "count": 2, "colors": ["Green"],
                    "rarity": ["Common"], "colorType": "MonoColor" },
                  { "type": "shards", "count": 4, "addMaxCount": 4 } ] }] }] },
  "failureDialog": { "text": "... (-2 Town Reputation)", "options": [{ "name": "(Quest Failed)",
      "action": [{ "addMapReputation": -2, "POIReference": "$(poi_1)" }] }] },
  "rewardDescription": "Shards, green commons & uncommons",           // display only
  "stages": [
    { "id": 1, "objective": "Leave", "anyPOI": true },                // leave the town (starts the clock)
    { "id": 2, "objective": "Hunt", "worldMapOK": true, "count3": 30,  // 30 s before the target despawns
      "enemyTags": ["BiomeGreen"], "prerequisiteIDs": [1] },          // random green enemy -> $(enemy_2)
    { "id": 3, "objective": "Travel", "here": true, "prerequisiteIDs": [2] } ]  // return to the offering town
}
```

Other Shandalar shapes: `Clear` quests pick a cave by `POITags: ["Cave", "BiomeGreen"]` with `count1`/`count2`
distance bias; `Defeat` uses `mixedEnemies` or a picked enemy with `worldMapOK`; `Arena` and `Event*` quests need no tags.
Vanilla has 53 entries (ids 1-27 repeatable templates, higher ids are story). Per-color text and rewards are
copy-pasted per template, not generated.

## 3. Random vs fixed, and seeding

| Aspect | Random? | Source |
|---|---|---|
| Which template a board offers | Random, uniform, **unseeded** | `Aggregates.random` (`MyRandom`, process-wide) |
| Whether the board re-offers after completing | Random 85% | `new Random()` (`:~145`) |
| Target POI | Random within tag set / distance band | `new Random()` in `setTargetPOI:126`, `Aggregates.random:135` |
| Target enemy | Random within tag set | `Aggregates.random` (`AdventureQuestData.java:380-383`) |
| Reward cards/gold/shards | Random, **unseeded** | `useSeedlessRandom = true` (`RewardData.java:192`) |
| Text, stage graph, counts, reputation | Fixed | JSON |
| Daily lock | Real-world date | `LocalDate.now()` |

Nothing in quest generation uses the world seed. Reloading a save re-rolls the offer (the lock is saved in
`nextQuestDate`, but the roll is not). The world seed only drives POI placement and board-map content
(`World.java:315-318`, `TileMapScene.java:~168` `setSeed(point.getSeedOffset())`). For reproducible quests you would
have to add a seeded `Random` (see section 6).

Save/serialization caveats: `nextQuestDate`, `questAvailability`, `maximumSideQuests`, `dialogQueue`, `mostRecentPOI`
are serialized with the controller; token dictionaries (`poiTokens`, `enemyTokens`, `otherTokens`) are shared by
reference with the template in the copy constructor (`:100-102`) and `poiBiomeTokens` is not copied at all, so a
board-offered copy can leak tokens between instances. Test two simultaneous quests of the same template.

| Enemies | `Concordia/world/enemies.json` has **no `questTags`** (0 matches) | Every `Defeat`/`Hunt` template falls back to *any* enemy (`AdventureQuestData.java:379-381`); `getBoostedSpawns` would also match nothing for tagged `mixedEnemies`. |
| Quest IDs | Story chain uses `issueQuest` in epilogues (`1000 -> 1001`) | Plane design reserves 1-27 for reused Forge templates, 1200+ for side quests (`DESIGN.md:589`). Note ID 28 is hard-coded as the new-game quest (`NewGameScene.java:366`, `SaveLoadScene.java:325`). |

| Flags | Seals `sealG/U/R/W` (+ black), `campCh`, `colX`, `colStart` (`DESIGN.md:595-596`) | `POI.questFlagsToActivate` can hide POIs by flag; quests can only test flags via `QuestFlag`/`MapFlag`/`CharacterFlag` stages. |

## 5. Gaps and risks for the Concordia design

| # | Gap / risk | Why it matters | Mitigation |
|---|---|---|---|
| G1 | **No eligibility check on templates** (`getQuestNPCResponse:545-556`) | Cannot say "only after Seal G", "only chapter 2", "not in zone X". A rolled template ignores campaign progress; the daily lock is burned anyway. | Java hook H1 (requirements). Data-only fallback: one template per progress band, board `questtype` per band (but boards are static per map). |
| G2 | **POI tags cannot express zone, tier, lock state** | `Cave`+`BiomeGreen` could pick a cave in a zone the player cannot reach yet (the door is locked) or one not yet unlocked, softlocking the quest. `allowInactivePOI` is off by default, so POIs hidden by `questFlagsToActivate` are skipped, but POIs behind gate/stage locks are not hidden. | Add tags `Zone<Color>`, `Tier1..3`, `Optional`, `NoQuest`; **never tag Warden gyms, gate passes, Champion area or story-critical maps as quest targets**; reuse `questFlagsToActivate` so a POI is inactive until its zone is open. |
| G3 | **Seals and Warden fights must not be quest targets or quest rewards** | `Clear` on a Warden gym would let the player bypass gym logic; reward `setQuestFlag sealX` would bypass the Seal. | Keep all Warden/gate/Champion/Archive POIs without `Cave`/`Dungeon` quest tags; restrict flag-setting to story quests; lint step in `quests.json` review. |
| G4 | **Quest rewards are unseeded and unscaled** | A flat `grantRewards` blob pays the same at Seal 0 and Seal 5; conflicts with the economy rule that "every grind source pays the same flat reward" (`DESIGN.md:597`). Card colors in `colors` are hard-coded per template, but Concordia's color unlocks are per player. | Use the flat currency rule: gold + shards only, plus a color-matched card chance via a `colors` list per template band. For player-color-aware rewards you need Java hook H3. |
| G5 | **Colors**: `RewardData.colors` is static; `$(playercolor)` token does not exist | Rewards or enemies in colors the player has not unlocked break the "colors are earned from Wardens" rule. | Bind the template to its board's zone color (data), or hook H3. |
| G6 | **Enemy tags absent** | `Defeat`/`Hunt` is effectively "random enemy of the plane", which can be a Warden-tier or champion deck. | Tag Concordia enemies in `enemies.json`: `questTags` such as `BiomeGreen`, `Tier1`..`Tier3`, `Trainer`, `NoQuest` on bosses; generator skips `NoQuest` (hook H2) or always `enemyExcludeTags: ["NoQuest"]` in templates (data-only). |
| G7 | **Board only at Mossgate, gate towns and Warden towns** (design) | The `quest` object is per map and `questtype` is the only filter. A generic `forest_town_generic` leaks Shandalar flavor into every town. | Place `quest.tx` only in those maps; use `questtype` values `concordia_hub`, `concordia_gate_<color>`, `concordia_warden_<color>`; set `questSourceTags` on every template. Leave other towns without the object. |
| G8 | Daily lock uses the **real date** | A player can play past midnight and see new offers; "repeatable jobs" cannot be tuned by in-game progress. | Acceptable for now; or hook H4 (lock by completed-count or by `campCh`). |
| G9 | Cap of 5 side quests is global and hard-coded | Not per zone. Fine for Concordia; change only if desired. | Hook H4 (config). |
| G10 | `Hunt` needs the world map | The sprite is spawned on the overworld (`worldMapOK`); in Concordia the route mazes are separate maps, so a hunt can despawn in 30 s. | Prefer `Defeat` with `worldMapOK:false` plus `POITags`, or `Clear`, or `Travel` for Concordia. |
| G11 | `Fetch` has no item source | No code places the item; it only checks inventory counts. | Combine with `Clear` in a cave (reward item through map loot) or skip. |
| G12 | Token dictionaries shared in the copy constructor (`:100-102`) | Wrong names in text when two copies of one template coexist. | Fix in Java (hook H5), or avoid offering the same template twice. |
| G13 | `Use` objective precedence bug (`AdventureQuestStage.java:380-382`) | Completes on the first event that is not a use. | Avoid `Use`; fix if ever needed. |
| G14 | Mossgate/Rootgate `questtype = forest_town_generic` is a vanilla value | If we add vanilla templates with that tag they would appear at Mossgate with Shandalar text (Shandalar flavor, wasteland/biome tags that do not exist in Concordia). | Do not import vanilla templates blindly (see 6.1). |

## 6. Implementation proposal

### 6.1 Template types to add (all new IDs 1200+, `storyQuest` omitted/false, `isTemplate: true`)

| Template | Stages | Targeting | Reward | Notes |

### 7.2 Proposal: town standing

| Aspect | Design |
|---|---|
| Metric | Existing key-0 value, **range -20..+50** (clamp in code, or by convention in data). Bands: Distrusted < 0, Neutral 0-9, Known 10-24, Trusted 25-39, Honored 40+. Price effect already saturates at +/-20, so bands above 20 add quests, not discounts. |
| Rises | Quest done +3 (hard +5); optional board job done +1; duels won vs the town's raiders +1 (cap 5 per day); donation (gold sink dialog, e.g. 500 gold = +1, cap per visit); returning a stolen card +2; clearing a route/cave in the town's zone color +2. |
| Falls | Quest failed -2 (hunt despawn, abandon); declined offer -1 (vanilla); crimes: stealing/ante cheat, attacking town NPC, leaving a ward in danger -3 to -5; zone-color actions: winning against that color's Warden's allies is neutral, but dueling a color's duelists deliberately (rival color) is not penalized, only Unsealed/raider help (-3). |
| Decay | None in vanilla. Optional: drift toward 0 by 1 per N real days or per chapter (`campCh`) so grinding does not saturate. |
| Save | Keep `PointOfInterestChanges.reputation[0]` (already saved per POI, per world). Mirror a coarse band into a character flag only if other systems need it (flags are bytes, `DESIGN.md:596`), e.g. `repMossgate` 0-4. |
